# Code review, 2026-09-03

A review of the Firebase Functions implementation in `functions/index.js`,
written before the planned Go port. The goal was to catch anything that
would hurt in production, not to polish code that is going to be replaced.
Items marked **fixed in port** are resolved by the Go design in
`docs/superpowers/specs/2026-09-03-go-port-design.md` rather than by
patching the JavaScript.

## Do soon

1. **Node 20 runtime is past end of life.** The function runs on `nodejs20`.
   Cloud Functions deprecated that runtime in April 2026 and has a
   decommission date later in 2026. Check the current runtime support
   schedule. **Fixed in port** (Cloud Run with a Go binary).
2. **Fire-and-forget Firestore writes can crash the instance.** The counter
   updates at `functions/index.js:61` through `:72` and at `:159` have no
   `.catch`. A rejected write becomes an unhandled promise rejection, which
   terminates the Node process. Because a v2 function serves up to 80
   concurrent requests per instance, one failed write can drop other
   visitors' redirects. Firestore's per-document write rate limit makes this
   likely for a popular link, such as a QR code on a poster at an event.
   One-line fix: add `.catch(err => functions.logger.warn(...))` to each.
   **Fixed in port.**
3. **No `.catch` on the main promise chain.** Any asynchronous error (a
   Firestore outage, an invalid regex in a `paths` document, a slug such as
   `__foo__` that Firestore rejects) leaves the request hanging until the 60
   second timeout instead of returning a 500. **Fixed in port.**
4. **Empty slug crashes.** A `/qr/` path with nothing after it, or any URL
   that reduces to an empty slug, calls `doc("")`, which throws. Verified
   live: it returns a 500. **Fixed in port** (empty and invalid slugs take
   the 404 flow).
5. **No `maxInstances`.** A public endpoint with unlimited scaling is a cost
   exposure under a flood. Set `maxInstances` and consider `minInstances: 1`
   because every cold start adds about a second to a redirect. **Fixed in
   port** (Cloud Run `--max-instances`).

## Worth doing

6. **No required checks or reviews on `main`.** Branch protection blocks
   force pushes but requires no status checks or reviews, and every merge
   deploys to production. Require the CodeQL and lint jobs at minimum.
7. **Long-lived service account key in CI.** The deploy workflows
   authenticate with a JSON key stored as a GitHub secret. Switch to
   Workload Identity Federation. **Fixed in port.**
8. **Preview deploys do not test function changes.** `hosting:channel:deploy`
   with `pinTag: true` pins to the production function. The `.env` write in
   `preview.yml` never reaches a deployed function. **Removed in port.**
9. **Firestore rules never deploy from CI.** The production deploy runs
   `--only functions:redirV2,hosting`. The deployed rules match the repo
   today, but the repo is not the source of truth. **Fixed in port** (deploy
   includes `firestore:rules`).
10. **Passthrough buffers whole upstream responses in memory** and forwards
    the visitor's `Authorization` header upstream. Acceptable while
    destinations are trusted and small. The port streams bodies; the header
    forwarding is kept on purpose and documented.
11. **No `Cache-Control` on QR images.** Every scan of the QR host re-renders
    the PNG. **Fixed in port** (`public, max-age=86400`).

## Cleanup and docs

12. `README.md` listed `firebase-admin@^12` and `firebase-functions@^6`; the
    lockfile has 13 and 7. Fixed in this branch.
13. The CodeQL workflow uses `actions/checkout@v3` and `codeql-action@v2`,
    both deprecated.
14. Behaviors that were undocumented before this review are now written down
    in `docs/behavior.md`: `paths` patterns without a named capture group
    never match (27 production rules are dead because of this; the port
    makes them work), the remainder matched against patterns includes the query
    string, first match wins in document ID order, slugs are not URL
    decoded, and a `statusCode` of 301 stops analytics once browsers cache
    the redirect.
15. Minor: the frame page's `<iframe .../>` is not a valid self-closing tag
    and the page has no doctype. It works because of quirks mode. **Fixed in
    port.**

## Verified during the review

- Deployed Firestore rules match `firestore.rules` (deny all).
- The deployed function is v2, `us-central1`, 256 MB, `nodejs20`.
- Production deploy succeeded on `firebase-functions` 7.x on 2026-09-03, so
  that major version bump is not a concern.
- `npm audit --omit=dev` reports no vulnerabilities.
- ESLint reports six `promise/no-nesting` warnings and no errors.
